你现在是这个项目的主程和架构师，请帮我从零开发一个 Windows 平台的 2D 电脑桌面宠物

## 一、当前阶段目标

目前只实现以下核心功能，不要提前开发 AI 聊天、宠物成长、语音、小游戏等功能：

1. 桌宠窗口与动画
2. 鼠标交互
3. 电脑状态监控与显示

要求项目结构清晰、模块解耦，为后续扩展 AI、行为系统、宠物成长等功能预留接口。

## 二、桌宠窗口

桌宠运行在 Windows 桌面上：

* 无边框窗口
* 背景透明
* 桌宠本身显示为透明 PNG/WebP 等素材
* 不显示传统窗口边框
* 支持自由移动
* 可以设置窗口始终置顶或普通桌面层级
* 支持系统托盘图标
* 可以通过右键菜单退出程序和打开设置
* 程序启动后桌宠出现在合理的默认位置
* 不影响其他窗口正常使用

请将“窗口管理”和“桌宠角色显示”分离。

## 三、动画系统

设计一个简单但可扩展的动画状态机。

至少支持以下状态：

* IDLE：待机
* DRAG：被鼠标拎起
* HAPPY：互动后的开心状态

当前可以先使用占位动画素材，但必须把动画系统设计好，使以后替换成真正的角色动画非常方便。

要求：

* 不同状态可以切换不同动画
* 支持帧动画
* 支持控制动画播放速度
* 动画状态与鼠标交互逻辑分离
* 后续可以很容易增加新状态

## 四、鼠标交互

这是当前版本的重点。

### 普通点击

点击桌宠时：

* 可以触发互动动画
* 暂时播放 HAPPY 动画
* 后续预留触发其他行为的接口

### 鼠标拖动

实现类似“拎起桌宠”的效果：

1. 鼠标左键按住桌宠
2. 桌宠进入 DRAG 状态
3. 桌宠跟随鼠标移动
4. 拖动过程中保持正确的鼠标相对位置，不要出现跳动
5. 松开鼠标后结束拖动
6. 根据需要回到 IDLE 或其他状态

重点：

“被拎起来”不是简单地让桌宠跟随鼠标，而是应该允许以后加入专门的 DRAG 动画，例如角色被拎住、身体下垂等。

请把 DragController / InteractionController 等逻辑独立出来，不要全部写在 UI 代码中。

## 五、电脑状态监控

增加一个可选的电脑状态显示系统。

第一阶段至少支持：

* CPU 使用率
* 内存使用率
* CPU 温度
* GPU 使用率
* GPU 温度

要求：

1. 每种状态都可以单独开启/关闭。
2. 用户可以选择显示哪些数据。
3. 桌宠旁边可以显示一个简洁的信息面板。
4. 数据定时刷新，不要每一帧读取系统数据。
5. 监控失败时不能导致程序崩溃，应显示“不可用”或隐藏对应项目。
6. CPU/GPU 温度等硬件数据需要考虑不同硬件和驱动导致的兼容性问题。
7. 将 SystemMonitor 独立成模块，未来可以增加网络速度、磁盘占用、电池状态等数据。

## 六、设置界面

当前版本制作一个简单设置窗口即可。

至少包含：

* 显示/隐藏 CPU
* 显示/隐藏 RAM
* 显示/隐藏 CPU 温度
* 显示/隐藏 GPU
* 显示/隐藏 GPU 温度
* 桌宠始终置顶开关
* 信息面板显示/隐藏

设置应该保存到本地配置文件，程序重新启动后保持之前的设置。

## 七、项目架构

请不要把所有代码写进一个文件。

建议至少按照以下职责拆分：

* App / Application
* PetWindow
* Pet / Character
* Animation
* StateMachine
* Interaction / DragController
* SystemMonitor
* Settings
* Tray / SystemTray
* Assets

具体目录结构可以根据你选择的技术栈调整，但必须做到：

UI、动画、交互、系统监控、配置管理相互独立。

## 八、技术要求

目标平台：

Windows 

请优先选择适合开发 Windows 2D 桌宠的技术栈，并说明选择理由。

如果使用 Python，优先考虑 PySide6，并选择合适的系统监控库。

如果某项功能需要 Windows API 或第三方库，请说明原因以及安装方式。

整个项目必须能够：

1. 本地直接运行
2. 后续方便打包成 Windows 可执行文件
3. 不依赖网络也能运行基础桌宠功能

## 九、开发方式

不要一次性生成一个巨大项目。

请按照以下方式开发：

第一步：
先分析需求并给出技术选型、项目目录结构和核心架构。

第二步：
实现最小可运行版本：
透明桌宠窗口 + 占位角色 + 基础动画。

第三步：
加入鼠标点击和拖动。

第四步：
加入 DRAG 状态和被拎起动画接口。

第五步：
加入 SystemMonitor。

第六步：
加入设置界面和本地配置。

每完成一个阶段，都确保项目可以运行，再继续下一阶段。

如果发现需求中存在技术风险，请先指出风险并给出解决方案，不要自行偷偷改变需求。

## 十、重要原则

这是一个准备持续迭代的项目。

请优先考虑：

* 简洁
* 稳定
* 模块化
* 可扩展
* 易于调试

不要为了当前功能过度设计。
